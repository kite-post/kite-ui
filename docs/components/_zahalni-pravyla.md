# Загальні правила компонентів

> Діють для кожного компонента `@kite-post/ui`. Специфікація компонента
> описує лише те, що відрізняється від цих правил або доповнює їх.
> Терміни «мусить / варто / можна» — як у [стайлгайді](../styleguide/README.md).

## 1. Іменування

- Компонент — `K` + назва в PascalCase: `KButton`, `KDatePicker`. Частини
  складених компонентів — з тим самим префіксом: `KDialog`, `KDialogTitle`.
- Файл — `src/components/<назва>/<KНазва>.vue`, поруч `index.ts`,
  `<KНазва>.test.ts`, `<KНазва>.stories.ts`, `types.ts`.
- CSS-клас кореня — `kite-<назва-kebab>` (`kite-button`), частини —
  `kite-<назва>__<частина>` (`kite-dialog__title`). Модифікатори класами не
  робимо, бо стан і варіант описують `data-*` атрибути (розділ 6).
- Пропси, події, слоти — англійською, у `camelCase` у TS і `kebab-case` у
  шаблонах. Опис і тексти — українською.

## 2. Спільні пропси

Якщо компонент має відповідну властивість, він бере саме ці назви і значення.

| Проп       | Тип                                                         | Типово      | Значення                                                                              |
| ---------- | ----------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------- |
| `size`     | `'sm' \| 'md' \| 'lg'`                                      | `'md'`      | Розміри зі стайлгайду 5.2 (32 / 40 / 48)                                              |
| `variant`  | залежить від компонента                                     | перший      | Візуальний варіант                                                                    |
| `tone`     | `'neutral' \| 'info' \| 'success' \| 'warning' \| 'danger'` | `'neutral'` | Тон статусу (стайлгайд 3.2)                                                           |
| `disabled` | `boolean`                                                   | `false`     | Вимкнено                                                                              |
| `readonly` | `boolean`                                                   | `false`     | Тільки читання                                                                        |
| `invalid`  | `boolean`                                                   | `false`     | Стан помилки (зазвичай приходить із `KField`)                                         |
| `required` | `boolean`                                                   | `false`     | Обов'язкове                                                                           |
| `loading`  | `boolean`                                                   | `false`     | Йде дія або завантаження                                                              |
| `as`       | `string \| Component`                                       | залежить    | Який елемент чи компонент рендерити (`'a'`, `RouterLink`)                             |
| `asChild`  | `boolean`                                                   | `false`     | Не рендерити свій корінь, а передати поведінку дочірньому елементу (Reka `Primitive`) |
| `id`       | `string`                                                    | авто        | Якщо не задано, генерується `useId()`                                                 |

- Булеві пропси завжди мають типове значення `false` і називаються без
  `is`/`has` (`disabled`, не `isDisabled`).
- **Ніколи:** пропси для довільного кольору, розміру в пікселях чи
  відступу. Кастомізація йде через токени (розділ 7).

## 3. Значення і `v-model`

- Основне значення — `modelValue` / `update:modelValue` (`v-model`).
- Додаткові керовані стани — іменовані моделі: `v-model:open`,
  `v-model:page`, `v-model:sorting`.
- Кожен компонент зі станом працює **і керовано, і некеровано**: якщо
  `v-model` не передано, стан живе всередині, а початкове значення
  задається пропсом `default*` (`defaultValue`, `defaultOpen`).
- Порожнє значення — `null`, а не `''` чи `undefined`. Виняток — текстові
  поля, де порожній рядок і є значенням.
- Дати на межі API — рядок ISO (`'2026-11-24'`, `'2026-11-24T14:05:00+02:00'`),
  а не `Date` і не `CalendarDate`.
- Телефон — рядок E.164 (`'+380671234567'`), номер накладної — без пробілів
  великими літерами (`'KT123456785UA'`), гроші — ціле число копійок
  (`125000` = 1 250 ₴).

## 4. Події

- Нативні події кореневого елемента (`click`, `focus`, `blur`, `keydown`)
  прокидаються як є, без перейменування.
- Власні події — дієслово в минулому чи `update:*`: `update:modelValue`,
  `update:open`, `remove`, `select`, `retry`. Без префікса `on`.
- Подія має одне значення як аргумент. Якщо потрібно більше — об'єкт з
  іменованими полями.
- Подія, яку можна скасувати (закриття діалогу з незбереженими даними),
  отримує об'єкт з `preventDefault()`.

## 5. Слоти

- `default` — основний вміст.
- Іконки — слоти `leading` і `trailing` або пропи `leadingIcon` /
  `trailingIcon` (компонент Lucide). Компонент обирає щось одне й
  документує.
- Складні частини — іменовані слоти (`header`, `footer`, `empty`, `actions`)
  або підкомпоненти (`KDialogFooter`). Підкомпоненти — коли частина має
  власну поведінку чи ARIA-роль, слоти — коли це лише місце для вмісту.
- Scoped-слоти віддають мінімально потрібні дані (`{ item, selected }`).

## 6. Атрибути стану для стилів

Кожен компонент виставляє стан у `data-*`, а стилі пишуться по них:

| Атрибут            | Значення                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| `data-size`        | `sm` / `md` / `lg`                                                                              |
| `data-variant`     | назва варіанта                                                                                  |
| `data-tone`        | тон                                                                                             |
| `data-state`       | `open` / `closed`, `checked` / `unchecked` / `indeterminate`, `active` / `inactive` (як у Reka) |
| `data-disabled`    | присутній, якщо вимкнено                                                                        |
| `data-invalid`     | присутній при помилці                                                                           |
| `data-loading`     | присутній при завантаженні                                                                      |
| `data-highlighted` | пункт під клавіатурним курсором (меню, списки)                                                  |

`aria-*` атрибути — для доступності, а не для стилів. Стилі по `aria-*`
дозволені лише там, де ARIA і є джерелом стану (`[aria-current="page"]`).

## 7. Стилі й токени

- Компоненти використовують лише семантичні токени стайлгайду і власні
  компонентні токени `--kite-<компонент>-<властивість>` (наприклад,
  `--kite-button-height-md`). Компонентні токени — єдиний спосіб, яким
  застосунок може змінити вигляд компонента.
- Стилі — scoped `<style>` у SFC з класами з розділу 1, без глобальних
  селекторів, крім базових стилів кіта.
- `class` і `style`, передані компоненту, потрапляють на корінь. Інші
  атрибути — на нативний інтерактивний елемент (`<input>`, `<button>`), якщо
  він не корінь (`inheritAttrs: false` + `v-bind="$attrs"`). Специфікація
  компонента каже, куди саме.
- Розміри — у `rem`, межі — `1px`, анімації — токенами руху з
  `prefers-reduced-motion`.

## 8. Інтеграція з `KField`

Контроли форм (`KInput`, `KSelect`, `KCombobox`, `KCheckbox`… і доменні поля)
читають контекст найближчого `KField` через `provide/inject`:

| З контексту   | Що робить контрол                           |
| ------------- | ------------------------------------------- |
| `id`          | Ставить на свій нативний елемент            |
| `describedBy` | `aria-describedby` = id підказки та помилки |
| `invalid`     | `aria-invalid="true"` і `data-invalid`      |
| `required`    | `required` і `aria-required="true"`         |
| `disabled`    | Вимикається                                 |

Власні пропси контрола мають пріоритет над контекстом. Без `KField` контрол
працює так само, але тоді назву йому дає `aria-label` або `aria-labelledby`.
Розробницьке попередження в консолі з'являється, якщо назви немає.

## 9. Тексти

- Жодного тексту в шаблоні компонента. Усі службові тексти («Закрити»,
  «Завантаження…», «Нічого не знайдено», «Обрано: {n}») мають ключ у словнику
  кіта й типове значення українською та англійською.
- Застосунок передає мову і може перевизначити тексти через
  `KConfigProvider`. Окремий екземпляр — через проп (`closeLabel`).
- Множина — через `Intl.PluralRules` (`uk`: one / few / many / other).
- У специфікаціях службові тексти перелічено в розділі «Тексти» з ключами
  (`dialog.close`).

## 10. Доступність (мінімум для кожного)

Чекліст зі стайлгайду (розділ 16). Окремо для компонентів:

- поведінка клавіатури — за WAI-ARIA APG для відповідного патерну.
  Специфікація перелічує клавіші;
- фокус після відкриття й закриття оверлеїв — за правилами `KDialog`;
- компонент не ставить `tabindex` > 0 і не ламає порядок фокусу.

## 11. Що мусить мати кожен компонент у репозиторії

1. Типізовані пропси, події й слоти (`defineProps<…>()`, `defineEmits<…>()`,
   `defineSlots<…>()`). Публічні типи — з `index.ts`.
2. Юніт-тести (Vitest + Vue Test Utils): рендер, варіанти, `v-model`,
   події, клавіатура.
3. Перевірка `axe-core` у тестах для типових станів.
4. Сторі Storybook для кожного варіанта й стану, в обох темах.
5. Специфікацію в `docs/components/` і сторінку на сайті документації.

## 12. Шаблон специфікації

Кожен файл `docs/components/<назва>.md` має розділи в такому порядку.
Розділ, який для компонента не має сенсу, пишеться з поясненням «немає,
бо…», а не пропускається.

1. **Призначення** — що робить і в яких застосунках.
2. **Коли використовувати / коли ні** — з альтернативою.
3. **Анатомія** — частини компонента.
4. **Варіанти й розміри**.
5. **Стани**.
6. **API** — пропси, події, слоти, `v-model`, підкомпоненти.
7. **Поведінка й клавіатура**.
8. **Доступність** — ролі, атрибути, що оголошується.
9. **Токени** — семантичні та компонентні.
10. **Тексти** — службові тексти з ключами.
11. **Так / не так**.
12. **Основа** — примітив Reka чи нативний елемент, залежності.
