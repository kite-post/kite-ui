# Kite · Стайлгайд інтерфейсу

> Версія 0.1 · задача 14, крок 3 · джерела: документація Kite 1.3 і NFR-11,
> [ресьорч 01](../research/01-pryntsypy-ui-ux.md) і [аудит палітри 02](../research/02-audyt-palitry.md).

Документ описує візуальну мову веб-застосунків Kite (kite-web, kite-business,
kite-ops) настільки детально, щоб за ним можна було зібрати токени й
компоненти без макета. Кожне значення тут існуватиме як токен у пакеті
`@kite-post/ui`. Якщо значення немає в цьому документі, його немає й у
інтерфейсі.

**Як читати вимоги.** «**Мусить**» і «**ніколи**» — обов'язково, порушення
вважається багом. «**Варто**» — типова поведінка, від якої можна відійти з
обґрунтуванням у PR. «**Можна**» — дозволений варіант.

## 1. Принципи

1. **Ясність понад декор.** Кожен елемент на екрані або допомагає виконати
   поточну задачу, або його там немає. Ієрархію будуємо відступом, розміром і
   вагою, а колір лишаємо на кінець.
2. **Один акцент.** Коралова — це «дія тут». На екрані чи в секції одна
   коралова кнопка. Якщо коралового багато, він перестає працювати.
3. **Легкість і швидкість** (бренд — повітряний змій). Інтерфейс відгукується
   миттєво, анімації короткі, порожнього простору багато, тіні м'які.
4. **Стан посилки — завжди людською мовою і завжди видно.** Колір статусу
   ніколи не йде без тексту й іконки.
5. **Одна система для клієнта й оператора.** Компоненти ті самі. Відрізняється
   лише композиція: клієнтські екрани просторі й крок за кроком, робочі
   щільніші, з таблицями й клавіатурою.
6. **Доступність — властивість компонента, а не застосунку.** Компонент із кіта
   вже має контраст, фокус, підписи й клавіатуру. Застосунок не мусить про це
   пам'ятати.

## 2. Токени: як влаштовані

### 2.1 Три шари

| Шар         | Приклад                   | Хто використовує                      | Чи змінюється з темою |
| ----------- | ------------------------- | ------------------------------------- | --------------------- |
| Примітиви   | `--kite-coral-500`        | Лише семантичні токени                | Ні                    |
| Семантичні  | `--kite-color-primary`    | Компоненти й застосунки               | **Так**               |
| Компонентні | `--kite-button-height-md` | Лише сам компонент (і перевизначення) | Через семантичні      |

- Компоненти й застосунки **ніколи** не використовують примітиви напряму.
  Виняток — ілюстрації та графіки.
- Значення **ніколи** не пишуться в коді компонента числом чи HEX. Можна лише
  `0`, `1px` для рамок і `100%`.

### 2.2 Іменування

```
--kite-{категорія}-{роль}[-{варіант}][-{стан}]

--kite-color-text-muted
--kite-color-primary-hover
--kite-space-4
--kite-radius-md
--kite-font-size-body
--kite-shadow-lg
--kite-duration-base
```

- Префікс `--kite-` у всіх токенах, щоб не конфліктувати з чужими стилями.
- Розміри відступів названі множником базової одиниці (`space-4` = 4 × 4 px =
  16 px). Решта категорій мають назви ролей (`sm`, `md`, `lg`).
- У TypeScript ті самі токени експортуються з `@kite-post/ui/tokens` як
  вкладений об'єкт (`tokens.color.primary`) зі значенням `var(--kite-…)`.
  Сирі значення для Flutter і графіків — `tokens.raw`.

### 2.3 Теми

- Тема перемикається атрибутом на `<html>`: `data-theme="light"` або
  `data-theme="dark"`. Без атрибута діє системна тема
  (`prefers-color-scheme`).
- Перемикаються **лише семантичні токени кольору й тіні**. Розміри, шрифти і
  рух від теми не залежать.
- Вибір користувача зберігається (`localStorage` ключ `kite-theme`: `light`,
  `dark` або `system`) і застосовується до першого рендеру скриптом у
  `<head>`, щоб не було спалаху світлої теми.
- Будь-яку частину сторінки можна примусово перевести в іншу тему тим самим
  атрибутом на контейнері (наприклад, темний банер на світлій сторінці).

Усі пари перевірено за WCAG 2.2: текст ≥ 4,5:1, контроли й великий текст ≥ 3:1.
Цифри — контраст до фону, на якому токен використовується.

#### Головна дія (coral)

| Токен                  | Світла              | Темна     | Примітка                                      |
| ---------------------- | ------------------- | --------- | --------------------------------------------- |
| `color-primary`        | coral-500 `#FF5A36` | coral-500 | Заливка головної кнопки, активні індикатори   |
| `color-primary-hover`  | coral-400 `#FF8265` | coral-400 | **Світлішає**, а не темнішає (див. нижче)     |
| `color-primary-active` | coral-300           | coral-300 |                                               |
| `color-on-primary`     | slate-950           | slate-975 | 5,63 / 6,03 на coral-500; 7,2+ на hover       |
| `color-primary-subtle` | coral-50            | coral-950 | Фон обраного пункту навігації                 |
| `color-primary-text`   | coral-800 `#942512` | coral-300 | Текст і іконка обраного пункту на subtle-фоні |

Чому стани світлішають: на кораловій лежить темний текст. Темніша коралова
зменшує контраст (ink на coral-600 — 4,11:1, не проходить), а світліша
збільшує. Той самий принцип — для всіх кнопок з темним текстом.

**Правила коралової:**

- **Мусить:** на кораловій заливці лише темний текст (`color-on-primary`).
  Білий текст на кораловій заборонено (3,10:1).
- **Ніколи:** коралова не позначає стан. Її немає в бейджах статусів,
  алертах, валідації, графіках «добре/погано».
- **Ніколи:** коралова не використовується як колір тексту на світлому фоні
  (3,10:1). Для тексту — `color-primary-text`.
- **Варто:** одна коралова кнопка на секцію. Інші дії — secondary або ghost.
- **Можна:** коралова як декоративний акцент великих площ (ілюстрації,
  герой-блоки маркетингу, логотип).

#### Статуси (тони)

Кожен тон має повний набір, і компоненти беруть лише його. Сирий колір шкали
для тону не беруть.

| Тон     | Значення                                 | `-solid` (заливка) | `-on-solid` | `-subtle` (фон) | `-border` | `-text` (текст, іконка) | Іконка Lucide    |
| ------- | ---------------------------------------- | ------------------ | ----------- | --------------- | --------- | ----------------------- | ---------------- |
| neutral | Чернетка, скасовано, нейтральні мітки    | slate-700          | white       | slate-100       | slate-300 | slate-700               | `circle-dashed`  |
| info    | Рух, інформація, нове                    | sky-700            | white       | sky-50          | sky-200   | sky-800                 | `info`           |
| success | Видано, оплачено, збережено              | green-700          | white       | green-50        | green-200 | green-800               | `circle-check`   |
| warning | Очікує дії, затримка, утримання          | amber-400          | slate-950   | amber-50        | amber-200 | amber-800               | `triangle-alert` |
| danger  | Помилка, втрата, пошкодження, незворотне | red-700            | white       | red-50          | red-200   | red-800                 | `circle-x`       |

Темна тема:

| Тон     | `-solid`  | `-on-solid` | `-subtle` | `-border` | `-text`   |
| ------- | --------- | ----------- | --------- | --------- | --------- |
| neutral | slate-300 | slate-975   | slate-800 | slate-700 | slate-300 |
| info    | sky-400   | slate-975   | sky-950   | sky-800   | sky-300   |
| success | green-400 | slate-975   | green-950 | green-800 | green-300 |
| warning | amber-400 | slate-975   | amber-950 | amber-800 | amber-300 |
| danger  | red-300   | slate-975   | red-950   | red-800   | red-300   |

Перевірено: `-text` на `-subtle` ≥ 6,1:1 (світла) і ≥ 8,5:1 (темна),
`-on-solid` на `-solid` ≥ 4,9:1. Окремо для `danger` у ролі кнопки:
`color-danger-hover` = red-800 (світла) / red-200 (темна), `color-danger-active`
= red-900 / red-100.

**Правила тонів:**

- **Мусить:** тон завжди йде з текстом, а в бейджах і алертах — ще й з
  іконкою (WCAG 1.4.1, а також червоне/зелене при дейтеранопії).
- **Ніколи:** тоновані фони `coral-50…200` поруч із `red-50…200`. Вони
  близькі, тому їх легко сплутати.
- **Варто:** у таблицях і списках — subtle-варіант (бейдж зі світлим фоном).
  Solid — лише для поодиноких сильних сигналів (лічильник непрочитаних,
  «Втрачено» в диспетчерській).

#### Фокус і виділення

| Токен                  | Світла            | Темна             |
| ---------------------- | ----------------- | ----------------- |

#### Графіки й дані

Категоріальна послідовність має фіксований порядок і не повторюється по
колу: sky-600, amber-500, green-600, slate-600, sky-300, amber-300. Нові
відтінки поза палітрою не вводимо. Якщо серій понад 6, решту об'єднуємо в
«Інше» або ділимо на кілька малих графіків. Коралова в графіках — лише для однієї виділеної серії
(«ваша посилка», «поточний хаб»). Детально графіки описуються на кроці
компонентів.

### 3.3 Пропорції

- ~60 % — `bg` і `surface`;
- ~30 % — текст, рамки, нейтральні поверхні (`slate`);
- ~10 % — акценти: коралова (дія), sky (посилання, інформація), тони статусів.

## 4. Типографіка

### 4.1 Шрифти

| Роль                        | Шрифт          | Ваги в проєкті     | Фолбек                                                                              |
| --------------------------- | -------------- | ------------------ | ----------------------------------------------------------------------------------- |
| Заголовки (`font-display`)  | Unbounded      | 500, 600           | Manrope, далі як у тексту                                                           |
| Текст і UI (`font-sans`)    | Manrope        | 400, 500, 600, 700 | `system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif` |
| Коди й номери (`font-mono`) | JetBrains Mono | 400, 500           | `ui-monospace, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace`            |

**Підключення — Google Fonts**, змінні шрифти, одним запитом. Кирилицю Google
віддає окремим `unicode-range`, тож браузер качає лише потрібні підмножини.

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link
  rel="stylesheet"
  href="https://fonts.googleapis.com/css2?family=JetBrains+Mono:wght@400..500&family=Manrope:wght@400..700&family=Unbounded:wght@500..600&display=swap"
/>
```

- `display=swap`: текст одразу видно фолбеком, шрифт підміняється, коли
  завантажиться.
- Пакет `@kite-post/ui` шрифтів не вбудовує. Посилання ставить застосунок у
  `index.html`, а кіт експортує цей фрагмент як константу
  `googleFontsHref` і документує його.
- **Ніколи:** не підключати інші ваги чи шрифти «на один заголовок».

### 4.2 Шкала

Розміри — лише з 1.3: 12 / 14 / 16 / 20 / 24 / 32 / 40. Висота рядка кратна 4.
Розміри в коді — у `rem` (1 rem = 16 px), щоб працювало масштабування тексту.

| Токен (`text-…`) | Розмір / рядок | Шрифт          | Вага | Трекінг   | Для чого                                                     |
| ---------------- | -------------- | -------------- | ---- | --------- | ------------------------------------------------------------ |
| `display`        | 40 / 48        | Unbounded      | 600  | −0,02 em  | Герой-заголовок лендингу, екран успіху («Накладну створено») |
| `h1`             | 32 / 40        | Unbounded      | 600  | −0,015 em | Заголовок сторінки                                           |
| `h2`             | 24 / 32        | Unbounded      | 600  | −0,01 em  | Заголовок секції, діалогу                                    |

| `h4`             | 16 / 24        | Manrope        | 700  | 0         | Підзаголовок у картці, заголовок у щільних інтерфейсах       |
| `body`           | 16 / 24        | Manrope        | 400  | 0         | Основний текст, значення полів, кнопки                       |

Решта не змінюється. Основний текст **ніколи** не менший за 16 px у полях
вводу на мобільних, інакше iOS масштабує сторінку при фокусі.

### 4.3 Правила

- **Unbounded — лише для заголовків ≥ 20 px.** Ніколи в кнопках, полях,
  таблицях, тексті абзаців. Заголовок Unbounded — до ~40 символів: кирилиця
  в ньому широка.
- **Довжина рядка тексту** — до 65 символів (`max-width: 65ch`).
- **Абзаци** розділяються відступом `space-4` (16 px), без червоного рядка.
- **Колір тексту** — лише `color-text`, `color-text-muted` або `-text` тонів.
  Ніякої прозорості для «сірішого» тексту.
- **Не більше трьох розмірів і трьох ваг** на одному екрані (без
  урахування номерів).
- **Табличні цифри** (`font-variant-numeric: tabular-nums`) — у таблицях,
  сумах, лічильниках, таймерах, датах у стовпцях. Токен-клас `kite-num`.
- **Обрізання**: однорядкове — `text-overflow: ellipsis` з повним текстом у
  `title` або підказці. Багаторядкове — `line-clamp` 2–3 рядки. Ніколи не
  обрізати номери, суми й коди.
- **Великі літери** — лише `overline`. Ніколи для кнопок, заголовків і
  цілих фраз.
- **Вирівнювання** — за лівим краєм. По центру — заголовок і текст порожнього
  стану, екрани успіху. По ширині — ніколи.

## 5. Простір і розміри

### 5.1 Відступи

Базова одиниця — 4 px. Інших значень немає.

| Токен       | px  | Типове використання                                                            |
| ----------- | --- | ------------------------------------------------------------------------------ |
| `space-0`   | 0   |                                                                                |
| `space-0.5` | 2   | Між іконкою й крапкою-індикатором, тонкі корекції                              |
| `space-1`   | 4   | Підпис ↔ поле, іконка ↔ текст у бейджі                                         |
| `space-2`   | 8   | Іконка ↔ текст у кнопці, між чіпами, поле ↔ підказка                           |
| `space-3`   | 12  | Внутрішній відступ щільних елементів, між кнопками                             |
| `space-4`   | 16  | Внутрішній відступ полів по горизонталі, між полями форми, гаттер на мобільних |
| `space-5`   | 20  | Внутрішній відступ щільної картки                                              |
| `space-6`   | 24  | Внутрішній відступ картки, між групами форми, гаттер на планшеті               |
| `space-8`   | 32  | Між секціями всередині сторінки, гаттер на десктопі                            |
| `space-10`  | 40  | Відступ сторінки зверху                                                        |
| `space-12`  | 48  | Між великими секціями                                                          |
| `space-16`  | 64  | Між блоками лендингу                                                           |
| `space-20`  | 80  | Герой-блоки                                                                    |
| `space-24`  | 96  | Герой-блоки на широких екранах                                                 |

**Правила:**

- **Внутрішнє ≤ зовнішнє.** Відступ між елементами групи менший, ніж між
  групами, щонайменше в 1,5–2 рази (поле ↔ поле 16, група ↔ група 24–32).
- **Мусить:** відступи — лише через токени. Корекції на 1–3 px для «щоб
  стало рівно» — ознака помилки висоти рядка чи іконки, а не привід для
  магічних чисел.
- **Варто:** відступ між елементами задавати контейнеру (`gap`), а не
  `margin` дочірнім елементам.

### 5.2 Розміри контролів

**Мінімальна ціль натискання — 40 × 40 px** (рішення команди: компроміс між
клієнтськими й робочими екранами; WCAG 2.2 AA вимагає 24 px, тож 40 px — з
запасом). Висота за замовчуванням для всіх контролів — 40 px.

| Розмір        | Висота | Горизонтальний відступ | Текст         | Іконка | Де                                                                                                              |
| ------------- | ------ | ---------------------- | ------------- | ------ | --------------------------------------------------------------------------------------------------------------- |
| `sm`          | 32     | 12                     | `body-sm`     | 16     | Лише на десктопі всередині щільних блоків (рядки таблиць, тулбари). Ціль добудовується до 40 px невидимою зоною |
| `md` (типово) | 40     | 16                     | `body`        | 20     | Усі кнопки, поля, селекти, вкладки                                                                              |

- Чекбокс і радіо: видима частина 20 × 20 px, ціль натискання — уся

- Перемикач (switch): 40 × 24 px, повзунок 20 px.
- Рядок таблиці: 48 px (типово), 40 px (компактний режим таблиці). Рядок

## 7. Форма: радіуси й рамки

### 7.1 Радіуси

| Токен         | px   | Де                                                               |
| ------------- | ---- | ---------------------------------------------------------------- |
| `radius-none` | 0    | Таблиці всередині карток, смуги                                  |
| `radius-xs`   | 4    | Чекбокс, мітки всередині полів, клавіатурні підказки (`kbd`)     |
| `radius-sm`   | 8    | **Поля вводу**, селекти, пункти меню, тултіп, скелетони (з 1.3)  |
| `radius-md`   | 12   | **Картки** (з 1.3), меню й поповери, алерти, тости               |
| `radius-lg`   | 16   | Діалоги, висувні панелі, великі промо-блоки                      |
| `radius-full` | 9999 | **Кнопки-«таблетки»** (з 1.3), бейджі, чіпи, аватари, перемикачі |

- **Вкладеність:** внутрішній радіус = зовнішній − внутрішній відступ (не
  менше 4). Наприклад, картка 12 з відступом 4 → вкладений блок 8.
- Кнопки-іконки — круглі (`radius-full`).
- Поле з кнопкою всередині (пошук) — поле `radius-sm`, кнопка всередині
  `radius-xs`.

### 7.2 Рамки

- Товщина: `border-width` 1 px для всього, 2 px — лише кільце фокусу й
  виділена (обрана) картка.
- Колір — токени `color-border*` (розділ 3.2). Декоративні рамки й
  роздільники — `color-border`, рамки контролів — `color-border-input`.
- Роздільник (`<hr>`, межа між секціями) — 1 px `color-border`. Якщо групу
  вже відділяє відступ ≥ `space-6`, роздільник не потрібен.

## 8. Поверхні й глибина

Глибина пояснює, що над чим лежить. У світлій темі її показує тінь, у темній —
світліша поверхня і рамка (тіні на темному майже не видно).

| Рівень | Токен тіні    | Світла тема                                                                  | Темна тема                           | Що                                      |
| ------ | ------------- | ---------------------------------------------------------------------------- | ------------------------------------ | --------------------------------------- |
| 0      | `shadow-none` | none                                                                         | none                                 | Картки на `bg` (лише рамка), таблиці    |
| 1      | `shadow-sm`   | `0 1px 2px rgb(14 26 43 / 0.06), 0 1px 3px rgb(14 26 43 / 0.08)`             | `0 1px 2px rgb(0 0 0 / 0.4)`         | Піднята картка, кнопка secondary        |
| 2      | `shadow-md`   | `0 4px 8px -2px rgb(14 26 43 / 0.08), 0 2px 4px -2px rgb(14 26 43 / 0.06)`   | `0 4px 8px -2px rgb(0 0 0 / 0.5)`    | Ховер інтерактивної картки, липка шапка |
| 3      | `shadow-lg`   | `0 12px 24px -6px rgb(14 26 43 / 0.14), 0 4px 8px -4px rgb(14 26 43 / 0.08)` | `0 12px 24px -6px rgb(0 0 0 / 0.6)`  | Меню, поповери, тости                   |
| 4      | `shadow-xl`   | `0 24px 48px -12px rgb(14 26 43 / 0.22)`                                     | `0 24px 48px -12px rgb(0 0 0 / 0.7)` | Діалоги, висувні панелі                 |

- Тінь тонована кольором `ink`, а не чорним: на теплому `paper` чорна тінь
  виглядає брудною.
- У темній темі рівні 3–4 обов'язково мають `surface-raised` і рамку
  `color-border`.
- **Ніколи:** тіні для декору, кольорові тіні, внутрішні тіні (крім
  натиснутого стану перемикачів).
- Картка за замовчуванням — рівень 0: `surface` + рамка `color-border` +
  `radius-md`. Тінь з'являється лише в інтерактивної картки на ховер.

## 9. Фокус

- **Мусить:** кожен інтерактивний елемент має видимий фокус при навігації з
  клавіатури (`:focus-visible`). Прибирати `outline` без заміни заборонено.
- Вигляд: `outline: 2px solid var(--kite-color-focus-ring); outline-offset: 2px;`
  з радіусом самого елемента. Контраст кільця до фону ≥ 3:1 в обох темах
  (4,1–7,6).
- Поля вводу: замість зовнішнього кільця — рамка `color-border-focus` плюс
  `box-shadow: 0 0 0 1px var(--kite-color-border-focus)`, тобто 2 px сумарно.
  Так кільце не налазить на сусідні поля.
- Поле з помилкою у фокусі — рамка й тінь кольору `color-danger-text`.
- Елементи всередині контейнера з `overflow: hidden` використовують
  `outline-offset: -2px`, щоб кільце не обрізалось.
- Липка шапка й нижні панелі не перекривають елемент у фокусі:
  `scroll-padding-top` = висота шапки + `space-4` (WCAG 2.4.11).

**Індикатор завантаження:** спінер з'являється через 300 мс після старту дії.
Швидші відповіді не мають «блимати». Скелетон — `color-bg-subtle` з
повільною пульсацією прозорості (1,5 с, `ease-in-out`). При
`prefers-reduced-motion` пульсація вимикається.

## 11. Рух

### 11.1 Токени

| Токен               | Значення | Для чого                                              |
| ------------------- | -------- | ----------------------------------------------------- |
| `duration-instant`  | 0 ms     | Зміни без анімації, `prefers-reduced-motion`          |
| `duration-fast`     | 100 ms   | Ховер, натискання, зміна кольору, перемикач           |
| `duration-base`     | 150 ms   | Поява тултіпа, чекбокс, розкриття дрібних елементів   |
| `duration-moderate` | 200 ms   | Меню, поповери, тости, акордеон                       |
| `duration-slow`     | 300 ms   | Діалоги, висувні панелі, переходи між кроками майстра |

| Токен         | Крива                            | Для чого                            |
| ------------- | -------------------------------- | ----------------------------------- |
| `ease-out`    | `cubic-bezier(0.16, 1, 0.3, 1)`  | Поява: швидкий старт, м'яка зупинка |
| `ease-in`     | `cubic-bezier(0.4, 0, 1, 1)`     | Зникнення                           |
| `ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | Переміщення, зміна розміру          |
| `ease-linear` | `linear`                         | Лише прогрес і обертання спінера    |

### 11.2 Правила

- Зникнення на один крок швидше за появу (діалог: поява 300, зникнення 200).
- Анімуються **лише** `opacity` і `transform`. Ширину, висоту й відступи
  ніколи не анімуємо. Виняток — акордеон через `grid-template-rows`.
- Типові патерни:
  - меню й поповер: `opacity 0→1` + `translateY(−4px→0)` + `scale(0.98→1)`
    від точки прив'язки;
  - діалог: скрім `opacity`, вікно `opacity` + `scale(0.96→1)`;
  - висувна панель: `translateX(100%→0)`;
  - тост: `translateY(16px→0)` + `opacity`, зникнення — `opacity`.
- **Мусить:** при `prefers-reduced-motion: reduce` усі переміщення й
  масштабування замінюються миттєвою зміною або fade ≤ 150 мс. Спінер
  крутиться далі: він передає стан.
- **Ніколи:** анімація довша за 400 мс в інтерфейсі, анімація при кожному
  ререндері, автоматичні каруселі.

## 12. Іконки

- **Набір — Lucide**, пакет для Vue (`lucide-vue-next`). Імпортуються
  поштучно, щоб не тягнути весь набір. Свої іконки малюються за сіткою
  Lucide (24 × 24, відступ 2 px, заокруглені кінці).
- **Контурні, товщина 1,5** на всіх розмірах (`stroke-width="1.5"`,
  `absoluteStrokeWidth` вимкнено). Заливки — лише всередині знаку, де без неї
  не обійтися (індикатор-крапка).
- **Розміри:** 16 (поряд із `body-sm`, `caption`, у `sm`-контролах), 20
  (типово: поряд із `body`, у кнопках і полях), 24 (навігація, окремі
  іконки-кнопки `lg`, порожні стани — до 48).
- **Колір** — `currentColor`. Іконка бере колір тексту поруч. Окремий колір —
  лише в тонах статусу (`-text`).
- **Вирівнювання з текстом:** центр по висоті рядка. Відступ до тексту —
  `space-2` (8 px), у бейджах і чіпах — `space-1` (4 px).
- **Доступність:**
  - декоративна іконка поруч із текстом — `aria-hidden="true"`;
  - кнопка лише з іконкою — **мусить** мати `aria-label` і підказку (tooltip)

- Знак — ромб змія з хрестом планок (`design/logo.svg`), без хвоста й

- **Охоронне поле** — 1/4 ширини знака з усіх боків.
- **Кольори:** коралова на світлому й темному фоні; білий або `ink` знак на

  палітри, не додавати тінь чи обведення, не ставити на фото без підкладки.

## 15. Тексти в інтерфейсі

**Голос (1.3):** коротко, на «ви», без канцеляриту. Говоримо як уважна
людина у відділенні, а не як система.

| Ситуація             | Правило                                           | Так                                                       | Не так                                  |
| -------------------- | ------------------------------------------------- | --------------------------------------------------------- | --------------------------------------- |
| Кнопка               | Дієслово + об'єкт, регістр речення                | «Створити накладну»                                       | «ОК», «Відправити», «Створити Накладну» |
| Діалог підтвердження | Заголовок — питання з дією, кнопки повторюють дію | «Скасувати накладну?» → «Скасувати накладну» / «Залишити» | «Ви впевнені?» → «Так» / «Ні»           |
| Помилка поля         | Що не так і як виправити                          | «Вкажіть вагу до 30 кг або оберіть тип "Вантаж"»          | «Невірне значення»                      |
| Помилка системи      | Що сталося, що робити, без кодів і вини           | «Не вдалося зберегти. Перевірте з'єднання і спробуйте ще» | «Error 503»                             |
| Успіх                | Коротко, з наступним кроком                       | «Накладну створено. Віднесіть посилку до 24 листопада»    | «Операція успішна»                      |
| Порожній стан        | Що тут буде + дія                                 | «Тут з'являться ваші відправлення» + «Створити першу»     | «Немає даних»                           |
| Нічого не знайдено   | Що шукали + як змінити                            | «За цими фільтрами нічого немає» + «Скинути фільтри»      | «Результатів: 0»                        |
| Статус посилки       | Людською мовою, теперішній час (7.1)              | «Їде до Львова»                                           | «IN_TRANSIT», «Прибуло до терміналу»    |
| Підпис поля          | Іменник, без двокрапки                            | «Телефон отримувача»                                      | «Введіть телефон отримувача:»           |
| Необов'язкове поле   | Позначаємо меншість словами                       | «Коментар (необов'язково)»                                | «Коментар*»                             |
| Плейсхолдер          | Лише приклад формату                              | «+380 67 123 45 67»                                       | «Введіть номер телефону»                |
| Посилання            | Описує, куди веде                                 | «Тарифи доставки»                                         | «Тут», «Детальніше»                     |

- **Регістр речення** скрізь: заголовки, кнопки, пункти меню.
- **Назви сутностей** — з 1.3 і глосарію (розділ 14): Kite Box, Kite Hub,
  Kite Business, накладна (а не «ТТН»), відділення.
- **Жодного тексту в коді компонентів.** Типові тексти кіта («Закрити»,
  «Завантаження…», «Обрано: 3») приходять пропсами або з i18n застосунку.
  Кіт має українські значення за замовчуванням і англійські як другу мову.

## 16. Доступність

Базовий рівень — **WCAG 2.2 AA**. Чекліст для кожного компонента (він же
розділ «Доступність» у специфікаціях кроку 5):

- [ ] Контраст тексту ≥ 4,5:1, великого тексту й контролів ≥ 3:1 в обох темах.
- [ ] Стан не передається лише кольором.
- [ ] Ціль натискання ≥ 40 × 40 px (розділ 5.2).
- [ ] Усе доступне з клавіатури, порядок фокусу = візуальний, пасток немає.
- [ ] Видимий `:focus-visible` (розділ 9), фокус не перекритий липкими блоками.
- [ ] Нативний елемент, де можливо. Якщо ні — патерн ARIA APG з правильними
      ролями, станами (`aria-expanded`, `aria-selected`…) і клавіатурою.
- [ ] Кожен контрол має доступну назву (`<label>`, `aria-label`, `aria-labelledby`).
- [ ] Помилки текстом, пов'язані з полем (`aria-invalid`, `aria-describedby`).
- [ ] Динамічні повідомлення — через `aria-live` (тости — `polite`, критичні
      помилки — `assertive`).
- [ ] Працює при збільшенні тексту до 200 % і ширині 320 px.
- [ ] `prefers-reduced-motion` поважається.
- [ ] Автоматична перевірка `axe-core` у тестах компонента без порушень.

## 17. Підключення в застосунку

```ts
// main.ts
import '@kite-post/ui/style.css' // токени (CSS-змінні) + базові стилі + компоненти
import { KButton } from '@kite-post/ui'
import { tokens } from '@kite-post/ui/tokens' // токени в TS, напр. для MapLibre
```

```html
<!-- index.html -->
<html lang="uk" data-theme="light">
  <!-- шрифти — розділ 4.1 -->
</html>
```

- Префікс компонентів — `K` (`KButton`, `KInput`), класів — `kite-`.
- Базові стилі кіта (reset, `body`, `::selection`, фокус, `kite-num`)
  підключаються разом із `style.css`. Застосунок свого reset не додає.
- Застосунок може перевизначити **лише семантичні й компонентні токени**
  (наприклад, щільність таблиць у kite-ops), а не внутрішні класи компонентів.
