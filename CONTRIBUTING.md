# Як долучитися

Кіт спільний для трьох застосунків, тож кожна зміна проходить один шлях: специфікація →
код → тести → історія → еталони → PR.

## Підготовка

```bash
make install
make verify       # те саме, що CI: токени, лінт, типи, тести, збірка
make storybook    # http://localhost:6006
```

## Гілки й PR

- `main` захищена: прямі коміти заборонені, злиття — через PR зі squash або rebase.
- Обов'язкові перевірки: **«Лінт, типи, тести, збірка»** і **«Візуальні регресії
  (Storybook)»**.
- Назва гілки: `feat/…`, `fix/…`, `docs/…`, `release/vX.Y.Z`.
- Коміти й описи PR — українською, у теперішньому часі: «KSelect: очищення з клавіатури».
- Запишіть зміну в `CHANGELOG.md` у розділ `[Unreleased]`.

## Новий компонент

1. **Специфікація** — `docs/components/<назва>.md` за шаблоном із 12 розділів (див.
   [`_zahalni-pravyla.md`](docs/components/_zahalni-pravyla.md)). Компонент потрапляє в
   кіт, лише якщо він потрібен щонайменше двом застосункам.
2. **Код** — `src/components/<назва>/K<Назва>.vue`:
   - Reka UI як основа поведінки й доступності, де є відповідний примітив;
   - класи Tailwind з префіксом `k:`, кольори й відступи — лише з токенів (стандартної
     теми Tailwind у кіті немає);
   - службові тексти — ключі в `src/lib/messages.ts` (uk і en);
   - пропси з JSDoc-описом українською — він потрапляє в документацію Storybook;
   - експорт у `src/components/index.ts`.
3. **Тести** — Vitest + `@vue/test-utils` поряд із кодом, з перевіркою axe
   (`expectNoA11yViolations`): ролі й назви, клавіатура, v-model, крайні стани.
4. **Історія** — `K<Назва>.stories.ts`: `Playground` з керуванням пропсами плюс історії
   для варіантів і станів. Оверлеї — ще й у відкритому стані, щоб їх було видно на
   знімках. Імена експортів — латиницею, українська назва — у `name`.
5. **Еталони** — після пушу гілки запустіть workflow «Оновити еталони» на цій гілці; він
   додасть знімки нових історій. Перегляньте їх у PR.
6. Якщо реалізація відійшла від специфікації — допишіть це в специфікацію.

## Зміни вигляду

Будь-яка навмисна зміна вигляду змінює еталони. CI на PR покаже різницю (артефакт
`visual-report`); якщо зміна правильна — «Оновити еталони» на гілці PR. Еталони знімаються
лише в Linux-образі Playwright (CI або `make visual-update` з Docker): знімки з macOS не
збігатимуться з CI.

## Токени

Правте `tokens/*.json`, потім `make tokens`. Згенеровані файли (`src/styles/tokens.css`,
`src/styles/theme.css`, `src/tokens/tokens.generated.ts`, `tokens/dart/lib/`, `tokens/dart/pubspec.yaml`)
комітяться; CI перевіряє, що вони актуальні, а `flutter analyze` — що Dart компілюється
(локально: `make dart`, потрібен Docker). Нові кольори — з перевіркою контрасту (WCAG 2.2 AA:
текст 4.5:1, межі й іконки 3:1).

## Реліз

```bash
make release V=0.8.0   # гілка release/v0.8.0: версія + CHANGELOG, PR
make tag               # після злиття: тег на main → публікація і Storybook
```

Перед `make release` перенесіть `[Unreleased]` у `CHANGELOG.md` під нову версію.
